## 第一件事：確認正式站真的是新版（照做，回報結果）
```bash
B=https://admin.meimai.com.tw/api/agent
H="X-Agent-Key: $MEIMAI_AGENT_KEY"
curl -s -H "$H" $B/me
curl -s -H "$H" $B/schema > /tmp/schema.json
```
檢查 `/tmp/schema.json`：
- 有 `resources.watermark`
- 有 `resources.car_media.docs`
- 頂層有 `image_input`
- `resources.car_blind_spot.endpoints` 裡**沒有** `spc`

再做一個無害測試：挑一筆目前 `status=1` 的行車記錄器，`PATCH $B/car_dashcam/{id}/status` 帶 `{"status":1}`。
- 回 `{"message":"status 已經是 1，未變更","unchanged":true}` ＝ 新版，繼續。
- 商品被切成停用 ＝ 還是舊版：馬上再打一次把它切回 1，停止使用新行為，回報老闆「正式站仍是舊版」。

最後 `POST $B/publish`：回 200 代表前台重新產生已接好；回 501 代表工程師還沒設定觸發網址，之後每次改完資料要回報「前台待工程師重新產生」。

## 第二件事：用新流程各做一次，回報結果（先問老闆用哪一筆測）
| 測試 | 怎麼做 | 預期 |
|---|---|---|
| 新增回 id | `POST /dealer`（名稱「測試_請刪」、`status=0`） | 回應有 `id`、`item`；做完 `DELETE /dealer/{id}` |
| 只送要改的欄位 | 對一筆商品 `PATCH /car_dashcam/{id}` body 只有 `{"memo_in":"…"}` | 讀回其他欄位沒變 |
| 圖片直接填 | `PATCH /car_dashcam/{id}` body `{"img":"https://外部圖網址"}` | `saved_images.img` 變成站內 `/storage/files/1/AgentImport/…` 網址，沒有 `warnings` |
| 車框沒送的格子保留 | 對一筆車框 `PATCH /car_frame/{id}` 只送 `imgArr[2][0]` | 讀回 `img`、`img1`、`img3` 原樣，`img2` 第 1 張更新 |
| 設定而非切換 | `PATCH …/status` 帶 `{"status":1}` 兩次 | 第二次回 `unchanged` |
| 刪除被擋 | 挑一個有車款的車廠 `DELETE /car_brand/{id}` | 回 400「仍被 N 筆車款使用中」，資料沒被刪 |
| 首頁事例上限 | 首頁已有 3 筆時，對第 4 筆 `PATCH /install_case/{id}/home` `{"is_home":1}` | 回 400 |
| 前台驗證 | `GET https://admin.meimai.com.tw/api/dashcam?brand=0` | 置頂商品排最前；停用商品的 `GET /dashcam/{id}` 回 404 |

每一項回報：請求、回應（去掉金鑰）、讀回結果。有一項不如預期就停下來回報，不要自己繞路。

## 之後的日常流程（每次都一樣）
1. `me` → `schema`（版本確認只在第一次或工程師說有更新時做）。
2. 不確定欄位意思：看 schema 的 `docs`，再看手冊第 7 章；還是不懂就問老闆，不猜。
3. 寫入：圖直接填、PATCH 只送要改的、新增用回傳 id。
4. 讀回驗證＋打前台公開 API 確認。
5. `POST /publish`；501 就回報待重新產生。
6. 回報格式照技能最後一段。

## 老闆要知道的分工（不要搞混）
- 這次更新的是**後台**（Laravel）。前台靜態網站要重新產生才看得到資料變化。
- 老闆本機 `frontend-v2` 的前台改動（安卓車框頁相簿式結果卡、頁尾原廠色圖示、美邁頁配色等）是**另一批**，由前台工程師合併部署；在正式站看到舊版畫面不代表後台沒更新。
- 頁面標題、副標、選單、按鈕文字、版面、顏色：你改不了，要找前台工程師（見《網站地圖與前後台對接對照》第 2、5 節）。
